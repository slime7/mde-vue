# 0034 — Bottom sheet 采用 min、normal、max 拖动档位与内容高度预览

- 状态: active
- 日期: 2026-09-11
- 替代: 无

## 背景

原有 expanded 只有 normal 与 full 两个具名档位：normal 直接按内容自然高度渲染，长内容默认就撑到最大高度；拖动只根据阈值在 normal 与 full 之间跳变，向上拖动落入帷幕还会触发一次误关闭，且关闭没有动画。使用者需要中间档、最小档和“内容完整显示”三类可预期高度，并希望拖动按落点吸附。

## 决策

expanded 增加 min（固定 64px）与 max（内容完整高度、以可用高度封顶），并把 normal 重定义为内容完整高度与可用高度一半的较小值；拖动只产生 min、normal、max，full 与自定义高度只由绑定变量设置。相邻档位以中点分界吸附，落点低于 32px 或向下快速甩动时请求关闭，full 与自定义高度保留当前高度作为候选避免跳档。拖拽关闭保留当前尺寸与偏移，让退出动画从可见位置继续播放。帷幕点击只接受按下与抬起都落在帷幕上的序列，避免拖拽误关闭。virtualExpand 改为按 min(内容高度, 可用高度) 布局面板并把下半部分移出屏幕，内容手势请求 max。档位与几何计算集中在内部 bottom-sheet-drag 模块。

## 考虑的方案

- 保留 normal = 内容自然高度、只新增 max：normal 与 max 高度相同，档位语义重复
- normal 保持自然高度并新增 min 与 max 但不改拖动：拖动仍按阈值跳变，落点不可预期
- 让拖动也能产生 full：与“full 只能由变量设置”的约束冲突

## 影响

- normal 的默认渲染高度改变：长内容默认停在半屏而不是撑满，内容继续在面板内部滚动；update:expanded 载荷由 normal/full 变为 min/normal/max，模板中依赖 full 载荷的使用者需要改为监听 max 或直接绑定变量；拖动与帷幕交互更可预期，误关闭消失，关闭动画从拖拽位置继续播放。
