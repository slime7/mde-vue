# 0037 — Bottom sheet 采用 AndroidX 式嵌套滚动手势

- 状态: active
- 日期: 2026-10-13
- 替代: 0034

## 背景

Bottom sheet 原有交互只允许拖动把手切换档位，内容区仅在 virtualExpand 模式下提供向上滑动 8px 直接跳到 max 的粗粒度手势；使用者期望移动端常见的“弹出固定高度后随触摸上下滑动切换高度至最高，随后滚动内容”的体验，并要求鼠标与键盘有等价操作。virtualExpand 让面板保留完整内容高度、仅用位移控制露出量，与默认按显式高度渲染的档位模型并存，维护两套拖动几何。

## 决策

移除 virtualExpand。Bottom sheet 默认提供 AndroidX ModalBottomSheet 式交互：触摸与手写笔在内容区按下并移动超过意图阈值后，折叠档向上拖动跟手展开、超出可用高度后剩余位移交给内容滚动，内容滚动在顶部时向下拖动跟手收缩，其余方向交还原生滚动；鼠标在内容区不建立手势以保留文本选择。折叠档滚轮向下请求展开（对应 AndroidX shouldExpandOnScroll）。把手在 Enter/Space 之外增加 ArrowUp/ArrowDown 按 min、normal、max 步进，full 与自定义高度向折叠方向先回到 max。触摸快速上甩在折叠档请求 max，快速下甩与落点低于关闭分区仍请求关闭；把手拖动保持原有中点吸附与阻尼几何。expanded 改为半受控：组件先更新内部档位再发出 update:expanded，未监听时组件保持切换后的高度；min、normal、max 档位定义与显式高度渲染沿用 0034 的档位模型。

## 考虑的方案

- 保留 virtualExpand 并在其上叠加嵌套滚动：两套高度模型与拖动几何长期并存，行为解释成本高
- 内容区手势只保留滑动阈值跳档（不做跟手）：实现最简单，但没有移动端的跟手手感
- 手势期间完全接管触摸滚动并自行实现惯性：可以支持手势中途从滚动切换为拖动，但需要重写滚动惯性且失去原生滚动手感

## 影响

- 破坏性变更：virtualExpand 属性与相关样式、档位偏移样式移除，滚轮展开成为默认行为；内容区拖拽在真实浏览器中只由面板层监听，消除此前根元素与面板层重复绑定造成的重复 update:expanded。触摸手势无法在浏览器原生滚动开始后中途接管，滚动到顶的手势进行中不会切换为拖动面板，需要下一次手势完成收回；该限制记录在组件文档中。
