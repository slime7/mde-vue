# 产品愿景

## 项目概述

`mdu-ui` 是供仓库所有者在自己的 Vue 应用间复用的组件库。它以 Material 3 为视觉基础，提供一致的 Vue API、动态主题和可由 AI 直接理解的使用文档。

## 要解决的问题

- 在多个个人 Vue 项目中复用一致的组件行为、视觉令牌和主题配置。
- 避免每个项目重复实现 Material 3 动态配色与基础交互状态。
- 让 coding agent 能通过精简、稳定且与实现同步的文档正确使用组件。
- 用可运行 demo 验证组件的不同状态，而不依赖外部展示站点。

## 使用者

- 主要使用者是仓库所有者及其维护的 Vue 3 客户端应用。
- 文档的主要读取者包括仓库所有者和协助编程的 AI agent。

## 目标与成功表现

- 组件具备清晰、稳定的 Vue 公共接口，并能通过私有 Git 固定提交安装。
- 主题可以由种子色、亮暗模式、配色变体和对比度统一驱动。
- 大部分组件可以通过统一的 `color` 属性选择语义色或建立不影响全局的局部动态配色。
- 原生 CSS 系统语义令牌与 Tailwind CSS v4 语义类表达同一套设计语义。
- 每个已实现组件都有中文使用文档、API 约束、自动化测试和可视 demo。
- `llms.txt` 与 `llms-full.txt` 能从 Markdown 权威来源重复生成并通过过期检查。

## 非目标与边界

- 不发布到 npm，也不为公开生态维护版本兼容承诺。
- 不支持 Vue 以外的框架、Web Components 适配层或 CDN 使用方式。
- 不支持 SSR、旧浏览器、本地化、IDE 插件或编辑器元数据。
- 不追求一次覆盖完整 Material 3 组件集合；当前优先完善 Button、Icon button、Button group 和 Split button 按钮体系。
- 不在库中持久化用户主题偏好，应用负责自己的存储策略。

## 核心原则

1. **Vue 优先**：公共接口遵循 Vue 3 的组件、插件和组合式 API 习惯。
2. **语义令牌优先**：组件依赖 Material 语义而非具体颜色值，主题切换不改变组件结构。
3. **源码与文档同源验证**：公共行为必须同时由测试、demo 和 Markdown 文档证明。
4. **保持范围克制**：只为实际个人项目需要增加能力，不承担通用框架生态成本。
5. **现代平台优先**：可以直接使用最新浏览器与现代 CSS 特性，不增加过时兼容代码。

## 当前阶段

当前阶段已经建立可安装的单包工程、Material 2025 主题基础、M3 Expressive 按钮体系、可视 demo、AI 文档生成和项目级 Agent 文档。后续组件应沿用统一的配色、尺寸、状态和组合抽象逐个增加。
