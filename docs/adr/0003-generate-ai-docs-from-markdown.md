# 0003 — 从 Markdown 生成 AI 使用文档

- 状态: active
- 日期: 2026-07-13
- 替代: 无

## 背景

项目既需要供人阅读的中文 VitePress 文档，也需要 agent 能一次发现和读取的 llms.txt 与 llms-full.txt。手工维护两套说明会造成组件 API 和限制不一致。

## 决策

将带 frontmatter 标记的 Markdown 使用页面作为唯一人工维护来源，由确定性脚本按显式顺序生成根目录 llms.txt 和 llms-full.txt。生成文件禁止手改，并在 CI 中使用检查模式验证没有过期。

## 考虑的方案

- 独立手工维护 AI 文档：可以针对 AI 单独措辞，但容易与使用页面发生重复和漂移。
- 只从源码注释提取 API：适合结构化签名，但无法完整表达安装、主题、限制和组合用法。
- 只提供 VitePress 页面：减少生成步骤，但 agent 缺少稳定的发现索引和完整单文件上下文。

## 影响

- 修改面向使用者的文档后必须重新生成 AI 文本并运行 docs:check。
- 只有明确标记的概述、安装、主题、Tailwind、组件 API 和限制进入 AI 文档，内部架构与纯交互页面保持排除。
- VitePress 构建需要复制生成文本和对应 Markdown，使相对链接在仓库与本地文档站中都可用。
