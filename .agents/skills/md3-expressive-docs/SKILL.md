# MD3 Expressive 官方文档与复刻

## 工作原则

- 以 Google Material 3 官方文档的实际页面为视觉和 API 证据来源；最终回答给出具体官方页面链接。
- 文档站可能由 AngularJS 动态渲染，不能把搜索摘要、页面源代码或一次性的文本抓取当作完整内容。使用浏览器实际打开并查看页面。
- 只处理 MD3 Expressive；跳过 MD2、RTL 和与当前问题无关的旧版本说明。
- mdu-ui 只使用 Vue 3、JavaScript、原生 CSS 和最新浏览器能力。复刻时遵守仓库的组件、主题令牌、测试和中文文档约束。

## 浏览官方文档

1. 从 Google Material 官方站点进入对应组件或 Expressive 页面。确认地址、页面标题和当前版本，记录最终页面 URL。
2. 等待动态内容渲染完成；如果文本不完整，先通过目录、组件导航或页面内链接定位，不要改用猜测。
3. 从上到下浏览页面。逐段滚动到内容即将进入视口的位置，等待懒加载完成，再观察并记录图片、动图、视频、交互演示和代码示例。
4. 对重要媒体进行实际视觉检查：记录形状、尺寸、间距、层级、状态变化、动效方向、时长/节奏和响应式变化。媒体没有加载时，继续滚动或等待后重试。
5. 对可交互示例逐一操作：默认、hover、focus-visible、pressed、selected、disabled、loading、错误、展开/收起和键盘操作（页面实际提供哪些就检查哪些）。必要时调整视口宽度，确认移动和桌面布局。
6. 记录参数时区分组件属性、事件、Slots/内容区域、状态和仅用于示例的内部实现。不要把 CSS 类、内部 DOM 或演示站实现细节误报为公共 API。
7. 若官方页面与 Material 令牌或组件规范页面存在引用关系，沿链接核对；仍以具体组件页面和规范页为准，并在回答中分别提供链接。

## 输出文档信息

先给结论，再给来源。至少包含：

- 组件名称、所属 MD3 Expressive 页面和官方链接。
- 已核对的参数：名称、类型/取值、默认行为、作用和限制；无法从页面确认的内容标记为“未确认”。
- 用户需要复刻时，分开说明结构、视觉令牌、交互状态、媒体中观察到的动画和响应式行为。
- 明确区分“官方页面明确说明”和“根据视觉或交互观察推断”；不要把推断写成官方 API。

## 复刻 mdu-ui 组件

1. 先检查仓库的 `AGENTS.md` 与 `docs/project/` 权威文档，再检查现有相近组件、基础层、主题令牌、测试和文档模式。
2. 对改变 `src/` 运行行为的工作遵循测试先行：先写能表达官方观察结果的测试，确认目标能力尚未实现时失败，再修改实现并验证。
3. 使用 Vue 3 Composition API 与 `<script setup>`；公共标签使用 `mat-*`，导出名与组件目录对应；只写 JavaScript，不引入 TypeScript。
4. 复用公开的 `--mat-ref-*`、`--mat-sys-*` 令牌表达共享设计值。组件内部变量可以组织实现，但不要将内部 class 或 `--mat-<component>-*` 记录成公共定制接口。
5. 难以用常规盒模型表达的 Expressive 形状或动画允许使用现代 CSS 的 `clip-path`、`border-shape`、CSS Anchor Positioning、View Transitions 或 Web Animations API；先确认它们不会破坏语义、焦点、命中区域和降级行为。
6. 动效必须服务于状态理解，避免只复制媒体中的装饰性运动；尊重 `prefers-reduced-motion`，为减少动效用户提供静态或简化状态。
7. 完整交付包括公共入口、样式、行为测试、同源 Vue 示例、中文组件文档和 AI 文档生成/检查；按改动范围运行 lint、测试、构建和文档检查。

不要把临时截图、页面缓存或抓取产物加入本项目技能目录；除非用户另有要求，也不要打包技能。
